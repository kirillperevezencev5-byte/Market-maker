MARKETPILOT — UX/UI 2.0

Комплексная модернизация интерфейса, пользовательского опыта и дизайн-системы

Ты работаешь над MarketPilot — SaaS-платформой для управления Telegram-сообществами.

Твоя задача — провести полный аудит пользовательского интерфейса и реализовать UX/UI 2.0: единую дизайн-систему, удобную навигацию, адаптивные интерфейсы, продуманный онбординг и качественный пользовательский опыт.

Главная цель: сделать MarketPilot визуально и функционально похожим на зрелый коммерческий SaaS-продукт, а не на набор отдельных страниц и модулей.

Не переписывай проект с нуля. Сохраняй рабочую бизнес-логику и интеграции.

⸻

2. DESIGN SYSTEM 2.0

Создай единую дизайн-систему MarketPilot.

Определи:

* Основную цветовую палитру.
* Дополнительные цвета.
* Цвета статусов.
* Типографическую шкалу.
* Размеры заголовков.
* Межстрочные интервалы.
* Отступы.
* Радиусы скругления.
* Тени.
* Границы.
* Состояния интерактивных элементов.
* Правила использования иконок.

Предусмотри полноценную поддержку тёмной темы.

Светлую тему реализуй, если она соответствует архитектуре и не создаёт чрезмерного усложнения.

Все компоненты должны использовать общие design tokens.

Не допускай ситуации, когда каждая страница имеет собственные несогласованные цвета и отступы.

3. GLOBAL NAVIGATION — НАВИГАЦИЯ

Переработай основную навигацию.

Пользователь должен быстро понимать:

* Где он находится.
* Какими сообществами управляет.
* Какие функции ему доступны.
* Какие задачи требуют внимания.
* Как перейти к нужному модулю.

Предусмотри логичную группировку:

Главная

* Dashboard.
* Обзор активности.

Управление

* Сообщества.
* Публикации.
* Планировщик.
* Модерация.

Инструменты

* AI Assistant.
* Автоматизации.
* Аналитика.

Коммерция

* Marketplace.
* Объявления.
* Финансы.

Рабочее пространство

* Команда.
* Роли и права.
* Настройки.

Адаптируй структуру под существующие функции проекта. Не добавляй несуществующие страницы ради заполнения меню.

Для мобильных устройств разработай отдельную удобную модель навигации.

4. DASHBOARD 2.0

Сделай главную страницу действительно полезной.

Пользователь должен сразу видеть:

* Количество подключённых сообществ.
* Активность за период.
* Запланированные публикации.
* Публикации, ожидающие модерации.
* Последние события.
* Основные показатели аналитики.
* Состояние автоматизаций.
* Состояние подписки.

Добавь блок быстрых действий:

* Создать публикацию.
* Подключить сообщество.
* Открыть модерацию.
* Создать автоматизацию.
* Посмотреть аналитику.

Предусмотри настройку расположения блоков, если это можно реализовать без чрезмерного усложнения.

Показывай только релевантную информацию с учётом прав пользователя и его тарифа.

6. ONBOARDING 2.0 — ПЕРВОЕ ЗНАКОМСТВО

Создай полноценный процесс первого запуска.

Новый пользователь должен пройти понятный путь:

1. Авторизация.
2. Знакомство с MarketPilot.
3. Создание или выбор Workspace.
4. Подключение Telegram-сообщества.
5. Проверка прав бота.
6. Настройка основных параметров.
7. Создание первой публикации.
8. Знакомство с основными инструментами.

Не заставляй пользователя проходить все шаги, если он хочет сразу перейти к Dashboard.

Добавь возможность пропустить необязательные этапы.

Показывай прогресс настройки.

Предусмотри контекстные подсказки, которые помогают понять назначение функций.

7. EMPTY STATES — ПУСТЫЕ СОСТОЯНИЯ

Проработай пустые состояния всех основных модулей.

Например:

* Нет подключённых сообществ.
* Нет публикаций.
* Нет автоматизаций.
* Нет данных аналитики.
* Нет объявлений.
* Нет участников команды.
* Нет транзакций.

Каждое пустое состояние должно объяснять:

1. Почему здесь пока нет данных.
2. Что пользователь может сделать.
3. Как выполнить первое действие.

Добавляй соответствующие CTA-кнопки.

Не используй бессмысленные заглушки.

8. FORMS & INTERACTIONS

Переработай формы и взаимодействия.

Требования:

* Понятные подписи полей.
* Inline-валидация.
* Объяснение ошибок.
* Корректная работа с клавиатурой.
* Защита от случайной потери данных.
* Подтверждение критических операций.
* Сохранение черновиков, где это необходимо.
* Понятные состояния отправки.

Уменьши количество лишних действий для пользователя.

Основные сценарии должны выполняться за минимальное количество шагов без ущерба безопасности.

9. MOBILE UX — МОБИЛЬНЫЙ ИНТЕРФЕЙС

MarketPilot должен качественно работать на смартфонах и внутри Telegram Mini App.

Проверь разрешения экранов:

* 320 px.
* 375 px.
* 390 px.
* 430 px.
* Планшетные размеры.
* Desktop.

Устрани:

* Горизонтальную прокрутку там, где она не нужна.
* Переполнение карточек.
* Сломанные таблицы.
* Слишком мелкие элементы управления.
* Неудобные формы.
* Конфликты фиксированных элементов.
* Проблемы с безопасными областями экрана.

На мобильных устройствах:

* Адаптируй таблицы в карточки или удобные представления.
* Переработай боковую навигацию.
* Сделай кнопки удобными для касания.
* Оптимизируй модальные окна.
* Учитывай особенности Telegram WebView.

Не ограничивайся простым уменьшением desktop-интерфейса.

10. MODULE CONSISTENCY — ЕДИНСТВО МОДУЛЕЙ

Проверь, чтобы все модули выглядели и работали как части одной платформы.

Особенно важно:

* Единый стиль AI Assistant.
* Единый стиль Scheduler.
* Единый стиль Analytics.
* Единый стиль Moderation.
* Единый стиль Marketplace.
* Единый стиль финансовых страниц.
* Единый стиль настроек.

У каждого модуля должны быть:

* Понятный заголовок.
* Краткое описание назначения.
* Основные действия.
* Фильтры, если нужны.
* Понятное отображение данных.
* Состояния загрузки.
* Пустые состояния.
* Обработка ошибок.

11. NOTIFICATIONS & FEEDBACK

Создай единую систему визуальной обратной связи.

Предусмотри:

* Успешные операции.
* Ошибки.
* Предупреждения.
* Информационные уведомления.
* Системные события.

Уведомления должны быть краткими и понятными.

Не показывай пользователю внутренние технические ошибки.

Не допускай дублирования уведомлений.

Для долгих операций показывай прогресс или состояние выполнения.

12. ACCESSIBILITY

Проведи базовую работу над доступностью:

* Контрастность текста.
* Читаемость шрифтов.
* Видимые состояния Focus.
* Управление клавиатурой.
* Подписи элементов форм.
* Альтернативные названия иконок.
* Корректная семантика элементов.
* Поддержка системного уменьшения анимаций.

Не используй цвет как единственный способ передачи статуса.

13. PERFORMANCE & MICROINTERACTIONS

Оптимизируй интерфейс:

* Уменьши ненужные перерисовки.
* Проверь тяжёлые компоненты.
* Оптимизируй загрузку изображений.
* Используй lazy loading там, где это оправдано.
* Устрани лишние сетевые запросы.
* Проверь размер Frontend bundle.
* Оптимизируй большие таблицы и списки.

Добавь умеренные анимации:

* Появление элементов.
* Переключение вкладок.
* Открытие модальных окон.
* Обновление карточек.
* Состояния кнопок.

Анимации не должны мешать работе и замедлять интерфейс.

14. REAL DATA INTEGRATION

Критически важно: UX/UI 2.0 не должен превращаться в декоративный редизайн.

Каждый элемент интерфейса должен использовать реальные данные Backend.

Проверь:

* Все кнопки.
* Все формы.
* Все фильтры.
* Все графики.
* Все таблицы.
* Все переходы.
* Все действия пользователя.

Не оставляй демонстрационные данные там, где должен отображаться реальный результат.

Не создавай фиктивные показатели ради визуального наполнения.

17. КРИТЕРИИ ГОТОВНОСТИ

UX/UI 2.0 считается завершённым, когда:

* У платформы единая дизайн-система.
* Все основные модули имеют согласованный интерфейс.
* Навигация понятна.
* Первый запуск не вызывает затруднений.
* Пустые состояния помогают начать работу.
* Формы и действия работают корректно.
* Мобильная версия удобна.
* Telegram Mini App работает стабильно.
* Все интерфейсы подключены к реальным данным.
* Нет критических визуальных ошибок.
* Основные E2E-сценарии проходят.
