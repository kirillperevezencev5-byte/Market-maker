MARKETPILOT — COMMUNITY MANAGEMENT 2.0

Полноценная система управления Telegram-сообществами и участниками

Ты работаешь над MarketPilot — SaaS-платформой для управления Telegram-сообществами.

Твоя задача — расширить существующие инструменты управления сообществами и создать полноценную систему Community Management 2.0.

Главная цель — предоставить владельцам и администраторам централизованный контроль над участниками, ролями, нарушениями, модерацией и активностью сообщества.

Важно: сначала изучи существующую архитектуру. Переиспользуй текущие механизмы Telegram Bot API, Workspace, RBAC, Audit Log и Smart Moderator. Не создавай дублирующие системы.

⸻

1. COMMUNITY AUDIT

Проведи аудит существующих функций:

* Подключение Telegram-сообществ.
* Получение информации о сообществах.
* Управление участниками.
* Управление администраторами.
* Smart Moderator.
* Anti-Scam.
* AutoClean.
* История событий.
* Настройки сообщества.
* Telegram Bot API.

Определи, какие возможности уже реализованы и какие необходимо добавить.

Проверь реальные ограничения Telegram Bot API и права подключённого бота. Не показывай функции, которые невозможно выполнить с текущими правами.

2. COMMUNITY DASHBOARD

Создай централизованную панель каждого сообщества.

Отображай:

* Название и аватар сообщества.
* Количество участников, если доступно.
* Количество администраторов.
* Новых участников за период, если данные собираются.
* Количество сообщений, если доступна статистика.
* Количество нарушений.
* Количество заблокированных пользователей.
* Активные правила модерации.
* Состояние Telegram-бота.
* Последние события.

Добавь быстрые действия:

* Открыть участников.
* Открыть модерацию.
* Настроить правила.
* Посмотреть аналитику.
* Управлять администраторами.

Все показатели должны рассчитываться на основе реальных данных.

3. MEMBER MANAGEMENT

Разработай полноценный интерфейс управления участниками.

Для каждого участника отображай доступную информацию:

* Telegram ID.
* Имя пользователя.
* Отображаемое имя.
* Дата вступления, если известна.
* Текущий статус.
* Количество предупреждений.
* Количество зарегистрированных нарушений.
* История действий модерации.

Предусмотри:

* Поиск.
* Фильтрацию.
* Сортировку.
* Просмотр профиля участника.
* Просмотр истории нарушений.
* Просмотр истории модерации.

Не пытайся получать или сохранять персональные данные, которые Telegram не предоставляет боту.

4. MEMBER ACTIONS

Добавь инструменты управления участниками:

* Предупреждение.
* Ограничение отправки сообщений.
* Временная блокировка.
* Постоянная блокировка.
* Разблокировка.
* Удаление участника из сообщества, если поддерживается API.

Для каждой операции:

1. Проверяй права пользователя MarketPilot.
2. Проверяй права Telegram-бота.
3. Проверяй возможность выполнения операции в Telegram.
4. Запрашивай подтверждение критического действия.
5. Фиксируй результат в Audit Log.
6. Показывай результат выполнения.

Для временных ограничений реализуй автоматическое снятие по окончании срока.

Не допускай повторного выполнения одной операции из-за повторных запросов.

5. WARNING SYSTEM

Разработай централизованную систему предупреждений.

Модератор должен иметь возможность:

* Выдать предупреждение.
* Указать причину.
* Выбрать категорию нарушения.
* Указать срок действия.
* Просмотреть предыдущие предупреждения.

Предусмотри настраиваемые правила:

* Первое предупреждение.
* Второе предупреждение.
* Третье предупреждение.
* Автоматическое ограничение после заданного количества предупреждений.

Пороговые значения должны настраиваться владельцем сообщества.

Добавь возможность отмены ошибочного предупреждения с обязательной записью в истории.

6. MODERATION RULE ENGINE

Развивай существующую систему Smart Moderator.

Предусмотри правила для:

* Спама.
* Флуда.
* Повторяющихся сообщений.
* Запрещённых слов.
* Подозрительных ссылок.
* Рекламы.
* Фишинга.
* Подозрительных вложений.
* Массовых упоминаний.
* Нежелательного контента.

Для каждого правила должны быть:

* Название.
* Описание.
* Условие срабатывания.
* Уровень серьёзности.
* Действие.
* Возможность включения и отключения.

Действия:

* Только зафиксировать.
* Предупредить.
* Удалить сообщение.
* Ограничить участника.
* Передать модератору.

Не допускай автоматических жёстких санкций по одному сомнительному сигналу.

Добавь возможность исключений для доверенных участников и администраторов.

7. MODERATION QUEUE

Создай единый центр рассмотрения нарушений.

Модератор должен видеть:

* Нарушение.
* Участника.
* Сообщество.
* Исходное сообщение, если оно доступно.
* Сработавшее правило.
* Уровень серьёзности.
* Рекомендованное действие.
* Историю предыдущих нарушений.

Доступные действия:

* Подтвердить нарушение.
* Отклонить срабатывание.
* Удалить сообщение.
* Предупредить участника.
* Ограничить участника.
* Передать старшему модератору.

Добавь фильтры по типу нарушения, дате, сообществу и статусу.

8. ADMIN MANAGEMENT

Создай интерфейс управления администраторами сообщества.

Отображай доступных администраторов и их реальные права.

Предусмотри:

* Просмотр администраторов.
* Просмотр их разрешений.
* Проверку прав бота.
* Сопоставление прав Telegram и ролей MarketPilot.

Не пытайся назначать или удалять администраторов через API, если соответствующая операция не поддерживается.

Важно разделять права Telegram и права внутри MarketPilot.

9. MEMBER ACTIVITY

Создай систему анализа активности участников на основании событий, которые MarketPilot действительно получает и сохраняет.

Показывай:

* Новых участников.
* Активность сообщений.
* Количество нарушений.
* Динамику предупреждений.
* Количество ограничений.
* Активность по периодам.

Предусмотри фильтры и поиск.

Не выдавай неполную статистику за полную статистику Telegram-сообщества.

Если данные начали собираться только после подключения MarketPilot, явно указывай период доступности статистики.

10. AUTOMATED MODERATION

Расширь автоматизацию модерации.

Предусмотри сценарии:

* Автоматическое приветствие новых участников.
* Проверка новых сообщений.
* Фиксация подозрительной активности.
* Предупреждение за нарушения.
* Временные ограничения.
* Автоматическое снятие ограничений.
* Передача сложных случаев модератору.

Все автоматические действия должны учитывать настройки сообщества, права бота и разрешения Workspace.

Предусмотри возможность выключить автоматическую модерацию для конкретного сообщества.

11. TRUST & REPUTATION

Добавь внутреннюю систему репутации участников.

Учитывай:

* Подтверждённые нарушения.
* Количество предупреждений.
* Повторные нарушения.
* Историю санкций.

Не создавай публичный рейтинг участников без отдельного решения владельца.

Не делай выводы о надёжности человека только по имени, фотографии или другим косвенным признакам.

Репутация должна быть объяснимой: модератор должен понимать, почему изменился показатель.

12. COMMUNITY RULES

Создай редактор правил сообщества.

Владелец должен иметь возможность:

* Создавать правила.
* Редактировать их.
* Удалять.
* Включать и отключать.
* Устанавливать приоритет.
* Назначать действия за нарушение.
* Устанавливать исключения.

Добавь предварительный просмотр правил.

Изменения должны сохраняться на сервере и попадать в Audit Log.

13. MEMBER NOTIFICATIONS

Добавь систему уведомлений участников.

Поддержи:

* Приветствия.
* Предупреждения.
* Уведомления об ограничениях, если Telegram позволяет их отправить.
* Уведомления об отмене санкции.

Предусмотри шаблоны сообщений.

Не отправляй пользователям лишние или повторяющиеся уведомления.

14. COMMUNITY SETTINGS

Создай единый экран настроек сообщества:

* Основные настройки.
* Правила.
* Модерация.
* Антиспам.
* Приветствия.
* Предупреждения.
* Автоматические действия.
* Исключения.
* Уведомления.

Настройки должны быть изолированы для каждого сообщества.

Предусмотри безопасное сохранение и возможность отмены изменений.

15. FRONTEND / UX

Создай следующие интерфейсы:

1. Community Dashboard.
2. Members.
3. Member Profile.
4. Moderation Center.
5. Warning History.
6. Admin Management.
7. Community Rules.
8. Moderation Settings.
9. Activity Analytics.
10. Automated Moderation.

Соблюдай дизайн-систему MarketPilot UX/UI 2.0.

Обеспечь мобильную адаптацию и совместимость с Telegram Mini App.

Все действия должны быть подключены к Backend.

16. SECURITY

Обязательно проверь:

* Workspace Isolation.
* RBAC.
* Проверку прав на конкретное сообщество.
* Проверку Telegram ID.
* Защиту от подмены идентификаторов.
* Проверку прав Telegram-бота.
* Защиту от повторных операций.
* Audit Log.
* Rate Limiting.

Модератор одного сообщества не должен управлять участниками другого сообщества.

17. DATABASE & BACKGROUND JOBS

Изучи существующую схему БД.

При необходимости расширь её сущностями:

* CommunityMember.
* MemberWarning.
* ModerationIncident.
* ModerationAction.
* CommunityRule.
* CommunityAdmin.
* MemberRestriction.
* MemberActivityEvent.
* ModerationExemption.

Названия адаптируй под существующую архитектуру.

Для фоновых задач реализуй:

* Автоматическое снятие временных ограничений.
* Обработку отложенных санкций.
* Повторные попытки при временных ошибках.
* Идемпотентность.
* Восстановление после перезапуска.

Не создавай отдельный Scheduler, если можно расширить существующий.

6. Временное ограничение.

14. Обработку повторных событий.
15. Изоляцию разных сообществ.
16. Корректность Audit Log.
17. Работу автоматической модерации.

Проверь негативные сценарии и регрессию существующих модулей.

Итоговая цель: превратить MarketPilot в полноценную платформу управления Telegram-сообществами с централизованной модерацией, управлением участниками и автоматизированными административными процессами.
